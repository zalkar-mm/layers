# ADR 008: Движок команд — в `entities/layer`, фичи — UI и привязка

**Статус:** Принято
**Дата:** 2026-09-26
**Этап ТЗ:** 4

## Контекст

ТЗ §3.1 кладёт `enable`, `disable`, `retry` в `features/layer-control`, а `enableAll`, `disableAll`, `retryFailed` — в `features/bulk-actions`. Обе группы должны делить одно состояние: карту `AbortController`, счётчик `requestId`, счётчик попыток, кэш. FSD запрещает импорт между слайсами одного слоя (architecture.md §2).

## Варианты

| Вариант | Минусы |
|---|---|
| Движок в `features/layer-control`, bulk-actions импортирует его | Кросс-импорт фич — нарушение FSD, ловится линтером |
| Два независимых движка | Два набора abort-контроллеров: `disableAll` не отменит запрос, запущенный одиночной командой — гонка |
| Движок в `shared` | `shared` не знает о предметной области |
| **Движок в `entities/layer/model`** | Команды — бизнес-логика сущности; `features` становятся тоньше |

## Решение

`createLayerService` живёт в `entities/layer/model` и отдаётся наружу одним экземпляром `layerCommands`. Фичи `layer-control` и `bulk-actions` содержат UI и вызывают команды этого экземпляра. Компоненты по-прежнему не содержат логики и не делают `dispatch` (ТЗ §13).

## Последствия

- Одна точка владения запросами: любая команда видит все запросы в полёте.
- Команды тестируются без React (`layer-service.test.ts`).
- Отступление от раскладки §3.1 ТЗ — только в месте файла, не в разделении ответственности.
