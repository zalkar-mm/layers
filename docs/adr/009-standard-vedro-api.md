# ADR 009: Штатный API vedro (`createVedro` → Provider + `useSelector`) со страховкой от V4

**Статус:** Принято
**Дата:** 2026-09-28
**Этап ТЗ:** 3 (пересмотр), решение заказчика от 28.09.2026 (ТЗ §15)

## Контекст

Заказчик попросил посмотреть пакет vedro и доделать решение. Выбрано прочтение «использовать штатный API»: компоненты читают стор через `createVedro(store)` → `Provider` + `useSelector`, а не через свои хуки на `useSyncExternalStore` ([ADR 002](002-use-sync-external-store.md)).

Ограничения штатного `useSelector` (подтверждены в [docs/vedro-findings](../vedro-findings/README.md)):

- V3: на каждый `dispatch` все смонтированные селекторы × 2 и `JSON.stringify` результатов × 2. Селектор, который отдаёт `LayerState` с GeoJSON, на 1000 загруженных слоях даёт 3,5 с на одно движение слайдера.
- V4: подписка в `useEffect` с `[]`. Обновление между рендером и подпиской теряется. В jsdom воспроизведено на строке слоя: она навсегда оставалась в «Загрузка…».
- V5: `useDispatch` — новая функция на каждый рендер.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Свои хуки на `useSyncExternalStore` (ADR 002) | Без tearing, O(1) чтение по ссылке, быстрее всего | Не штатный API — заказчик просит другое |
| Чистый штатный `useSelector` | Ноль своего кода подписки | V4: строка может застрять в «Загрузка…»; V3 при больших селекторах |
| **Штатный `useSelector` + тонкая страховка от V4** | Штатный API, обновления не теряются | ~20 строк страховки; сериализация видов на каждый `dispatch`; +1–3 мс на 1000 слоях |

## Решение

`bindVedroStore(store)` в `shared/lib/vedro` вызывает штатный `createVedro` со стором-синглтоном и отдаёт `{ Provider, useSelector }`. `Provider` получает тот же экземпляр, поэтому команды вне React и UI работают с одним стором.

Подписку держит штатный `useSelector`. Страховка от V4 (решение пользователя): на рендере значение сверяется со свежим `selector(store.get())` через `JSON.stringify`, при расхождении берётся свежее; после подписки эффект проверяет, не пришло ли обновление между рендером и подпиской, и перерисовывает.

Селекторы отдают маленькие виды без GeoJSON: `LayerRowView` для строки, сводка, оверлей карты, статус на карте. Так V3 сериализует несколько полей, а не сетку.

Цена в jsdom (медиана `setOpacity`, 1000 загруженных слоёв): 3,33 мс против 2,42 мс у `useSyncExternalStore` и 3474 мс у `useSelector`, отдающего весь `LayerState`. В браузере на 1000 слоях — +1–3 мс на действие, все действия в прогретом состоянии меньше 16 мс ([замеры](../../tests/perf/RESULTS.md)).

## Последствия

- **V3 диктует селекторы.** Селектор возвращает маленький вид без данных слоя. Селекторы тотальные: выполняются внутри каждого `dispatch`, в том числе для исчезнувшего слоя, и не бросают. Мемоизация сводки и оверлея — `WeakMap` по `byId`: vedro вызывает селектор для прошлого и нового состояния поочерёдно, одна запись «последнего входа» промахивалась бы.
- **Страховка V4** — в `bindVedroStore`. Без неё падают `layer-row.test.tsx` и тест V4 в `hooks.test.tsx`.
- **`useDispatch` не используется.** Все изменения — командами вне React (V1, V5).
- **Провайдеры.** `LayerStoresProvider` (слои, лог событий, статистика кэша), провайдеры фич `chaos-settings` и `stress-mode`, сборка — `app/state/store-providers.tsx`. Порядок: `ThemeProvider > StoreProviders > RouterProvider`. Тесты рендерят через `renderWithStores` из `tests/support`.
- **Кэш** остаётся вне vedro ([ADR 006](006-swr-cache.md)); для UI его статистика публикуется в маленький стор `layerCacheStatsStore`.
- **Бюджет рендеров сохранён.** Единственное отличие: при трёх ответах внутри одного `act` шапка перерисовывается 2 раза вместо 4 — React склеивает `setState` штатного хука.
- **ESLint:** импорт `vedro` и `vedro/*` — только в `src/shared/lib/vedro`, `tests/perf`, `docs/vedro-findings`; `useSyncExternalStore` в `src` запрещён (импорт, `React.useSyncExternalStore`, деструктуризация).
- Проверяется: `create-store.test.tsx`, `hooks.test.tsx`, `layer-row.test.tsx`, `row-view.test.ts`, тесты бюджета рендеров §8, `VITE_PERF=1 yarn perf`, `PERF=1 yarn e2e perf.spec.ts`.
