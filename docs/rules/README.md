# Правила проекта

Точка входа в `docs/rules/`. Каждый файл читается по требованию, в контекст целиком не грузится.

## 1. Как устроены правила

- **У каждого факта одно место.** Правило живёт в одном файле, остальные ссылаются на него (`code-style §3`). Копия правила в двух файлах — путь к расхождению.
- **Блокер подкреплён проверкой.** Если правило помечено ❌, его ловит ESLint, steiger, TypeScript или тест. Правило без проверки помечается «на ревью».
- **Документы описывают реальное состояние.** То, чего ещё нет в коде, помечено `[этап N]`.
- **Каждый файл заканчивается разделом «Что запрещено».**

## 2. Правила для AI-агента

1. **Не выдумывай в пробелах.** Ответа нет в правилах и ТЗ → решение обратимое и техническое: прими, запиши в теле коммита и в `AI_LOG.md`. Продуктовое или необратимое → остановись и спроси.
2. **Правило одного анализа.** Перед созданием файла проверь, что нужного нет в `shared/ui`, `shared/lib`, `entities/*`.
3. **Правило двух.** Одна и та же логика появилась во втором месте — выносится в общее в том же коммите. Третьего раза не бывает.
4. **Скопировать соседний файл и поправить пару строк — это долг, а не переиспользование.**
5. **Не следуй устаревшему коду молча.** Код расходится с правилом → правило важнее, сообщи.
6. **Результат субагента не принимается на слово.** «Тесты проходят» — правда только после собственного запуска `yarn check`.
7. **Документацию не обновляют задним числом.** Изменил поведение или конфиг — обнови правило в том же коммите.

## 3. Расхождения

| Конфликт | Что делать |
|---|---|
| Код ↔ правило | Правило важнее. Приводим код, если он в зоне задачи; иначе сообщаем |
| Правило ↔ правило | Не решать самому. Остановиться и спросить |
| Правило ↔ ТЗ | Остановиться и спросить |
| Правило ↔ фактический стек (версия, API библиотеки) | Предложить правку правила первым коммитом `docs(rules): …` |
| ТЗ ↔ реальность (например, находка vedro опровергнута) | Сообщить и предложить правку ТЗ, не обходить молча |

## 4. Честность

- Цифры производительности, покрытие, результаты тестов — только из реального запуска, с указанием машины и браузера.
- «Проверено» пишется, только если команда запускалась.
- `AI_LOG.md` описывает реальную работу, включая ошибки AI и то, как они пойманы.
