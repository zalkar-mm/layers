# ADR 001: Нормализованный стор `ids + byId`

**Статус:** Принято
**Дата:** 2026-09-26
**Этап ТЗ:** 3

## Контекст

Слоёв 3, в стресс-режиме — 100 и 1000 (ТЗ §10.2), набор меняется во время работы. vedro фиксирует ключи верхнего уровня при создании стора: новый ключ через колбэк или объект даёт исключение (V2, [тест](../vedro-findings/v2-new-top-level-key.test.ts)). Строке слоя нужно подписываться только на свой слой (ТЗ §8).

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Ключ на слой (`temperature`, `wind`, …) | Подписка `store.on('wind')` из коробки | Набор слоёв нельзя поменять без пересоздания стора (V2); строковый `dispatch(key, value)` ключ добавит, но без проверки и вне типов |
| Массив слоёв `layers: LayerState[]` | Просто | Поиск по id O(N), изменение слоя пересоздаёт массив — ссылки остальных элементов сохраняются, но порядок и данные смешаны |
| **`ids` + `byId`** | Порядок отдельно от данных; O(1) доступ; набор меняется одним `dispatch` | Нужно аккуратно сохранять ссылки при обновлении |

## Решение

`{ ids: readonly LayerId[]; byId: Record<LayerId, LayerState> }`. Все изменения — через `updateLayers`: он копирует `byId` один раз и заменяет только изменённые слои, `ids` не трогает. Если ни один слой не изменился, `dispatch` не делается.

## Последствия

- Строка слоя берёт снимок `byId[id]`: при изменении другого слоя ссылка та же, React не перерисовывает строку.
- Список (`useLayerIds`) перерисовывается только при смене набора слоёв.
- Каждое изменение копирует `byId` — O(N) по ключам. При 1000 слоёв это копия объекта из 1000 ссылок на действие; замер — этап 8.
- Проверяется тестом R9 (`entities/layer/model/store.test.ts`).
