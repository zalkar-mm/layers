# ADR 006: Кэш stale-while-revalidate вне стора

**Статус:** Принято
**Дата:** 2026-09-26
**Этап ТЗ:** 4

## Контекст

Задание требует запрос к API при каждом включении слоя. Без кэша повторное включение показывает пустую карту до ответа (300–2000 мс).

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Свежий кэш → запрос не отправляем | Мгновенно, без сети | Нарушает формулировку задания |
| **Stale-while-revalidate** | Прошлые данные видны сразу, запрос всё равно идёт | Два источника данных в UI: stale и свежие |
| Кэш внутри стора vedro | Одно место состояния | Каждая запись оповещает всех подписчиков стора; кэш — не UI-состояние |

## Решение

Отдельный модуль `createLayerCache` в `entities/layer/model`, в памяти, вне vedro. При включении свежая запись попадает в `loading.stale`, запрос идёт как обычно. TTL 5 минут, просроченная запись удаляется при чтении. LRU на 50 записей — иначе стресс-режим на 1000 слоёв растит память без ограничений. Запись — только после проверки `requestId`. Выключение слоя кэш не очищает. Кэш можно выключить (R15). Команды получают кэш зависимостью — тесты не влияют друг на друга.

## Последствия

- `LoadState` несёт `stale: CachedData | null` в `loading` и `error` — поле обязательное, компонент не может забыть его проверить.
- Счётчик «в кэше: N из M» подписывается на кэш через свой `subscribe`, а не через стор.
- Проверяется тестами R10–R15.
