# Состояние и асинхронность

Смежные темы: [architecture.md](architecture.md), [testing.md](testing.md). Что именно делать — ТЗ §4–§6; здесь — как писать код.

## 1. Где живёт логика

Цепочка: **UI → команда → стор ← подписчики (`useSelector`, MapSync)**. Mock API сбоку, вызывается только командами.

| Кто | Можно | Нельзя |
|---|---|---|
| `ui/` | Читать состояние хуками, вызывать команды, локальное **визуальное** состояние (`useState` для открытости раскрывашки) | Бизнес-правила, запросы, таймеры загрузки, прямой `dispatch`, знание о кэше |
| Команды: движок слоёв `entities/layer/model/loading/layer-service` ([ADR 008](../adr/008-command-engine-in-entity.md)), команды фич `features/*/model` | Async/await, `AbortController`, кэш, таймеры, синхронный `dispatch` | Импорт React, чтение DOM |
| Стор (`entities/layer/model/state`, `model/store`) | Хранить состояние, чистые функции переходов | Асинхронность, побочные эффекты |
| `shared/api` | Запрос, задержка, abort, типизированная ошибка | Знание о сторе, кэше, командах |

Если `useState` в компоненте «знает про домен» — его место в `model`.

Команды — чистые модули без React. Их можно вызвать и протестировать без рендера. Жизненный цикл с таймерами тоже в `model`: спам-клик Chaos-панели запускают и останавливают `spamClick` и `stopSpam`, UI только вызывает их (`stopSpam` — при размонтировании).

Экземпляры собираются в одном месте — `entities/layer/model/runtime.ts`. Зависимости передаются явно: `createLayerApi({ findConfig })` получает поиск конфигурации в активном реестре, `createLayerService` — API, кэш, лог событий и планировщики. Синхронизация URL запускается явно в `app/main.tsx` (`startBrowserUrlSync`), а не побочным эффектом импорта.

## 2. vedro

`vedro@1.1.0`, версия зафиксирована точно. Поведение подтверждено тестами в [`docs/vedro-findings/`](../vedro-findings/README.md) (задача 0.8). Подписка компонентов — штатный API ([ADR 009](../adr/009-standard-vedro-api.md)).

- Только **синхронный** `dispatch`. Асинхронщина — в командах (V1).
- Форма стора: `ids` + `byId`. Новые ключи верхнего уровня не добавляются (V2).
- Стор создаётся `createVedroStore`, привязка к React — `bindVedroStore(store)` из `@/shared/lib/vedro`: штатный `createVedro` + страховка от V4. Прямой импорт `vedro` и `vedro/*` вне `shared/lib/vedro` запрещён ESLint.
- Компоненты читают стор только через `useSelector` из привязки. `useSyncExternalStore` в `src` запрещён ESLint.
- `useDispatch` не используется: изменения — только командами вне React (V1, V5). `dispatch` не передаётся пропсами.
- `Provider` привязки получает стор-синглтон: команды и UI работают с одним экземпляром. Провайдеры слайса собираются в `app/state/store-providers.tsx`.
- Unsubscribe оборачивается в идемпотентный guard (V6).
- Подписка вне React — `store.on(...)` (V7), только в модулях `model` (MapSync, URL). Колбэк вызывается сразу при подписке и на каждый `dispatch` с этим ключом, даже без смены ссылки — сравниваем сами.
- Вне хуков состояние читается через `store.get('byId')`, а не `store.get()`: без ключа возвращается новая копия на каждый вызов (N1).

## 3. Селекторы

- **Маленький вид без данных слоя.** Штатный `useSelector` на каждый `dispatch` выполняет все смонтированные селекторы и сериализует результат (V3). Селектор отдаёт примитив или плоский объект (`LayerRowView`, сводка, оверлей карты, статус на карте), никогда `LayerState`, `LoadState` или GeoJSON: на 1000 загруженных слоях это 3,5 с против 3 мс на действие.
- **Тотальный.** Селектор выполняется внутри `dispatch` для всех строк, в том числе для слоя, которого уже нет в наборе: он возвращает вид по умолчанию, а не бросает.
- **Стабильный результат.** Производные по всему списку (сводка, оверлей) мемоизируются `WeakMap` по `byId`: vedro вызывает селектор для прошлого и нового состояния поочерёдно.
- **Structural sharing:** изменение слоя A создаёт новые объекты только для `byId` и `byId[A]`. Инвариант покрыт тестом (R9).

## 4. Гонки

Два независимых механизма, оба обязательны:

1. `AbortController` на слой — в `Map` вне стора. Новый запуск и `disable` отменяют предыдущий.
2. `requestId`-токен. Результат пишется, только если слой всё ещё в `loading` с тем же `requestId`. Иначе результат отбрасывается и **не пишется в кэш**.

`AbortError` — не ошибка: не переводит слой в `error`, не увеличивает `attempt`.

Любой async-путь команды тестируется на фейковых таймерах и фиксированном seed ([testing §2](testing.md#2-unit-тесты-команд-и-гонок)).

## 5. Кэш

Модуль вне стора vedro, внедряется в команды зависимостью (фабрика или синглтон с `reset()` для тестов). Стратегия и параметры — ТЗ §5.3.

## 6. Ресурсы

Подписка, таймер, `AbortController`, экземпляр карты — у каждого есть явное освобождение. Утечки проверяются повторным монтированием в StrictMode.

## Что запрещено

- ❌ `dispatch(async …)` — ревью, тест.
- ❌ Импорт `vedro` вне `shared/lib/vedro`, `useSyncExternalStore` в `src` — ESLint.
- ❌ `useDispatch`; селектор, возвращающий `LayerState`, `LoadState` или данные слоя — ревью, тест бюджета рендеров.
- ❌ Загрузка в `useEffect` компонента — ESLint + ревью.
- ❌ `dispatch` в пропсах, логика в `ui/` — ревью.
- ❌ Запись результата без проверки `requestId`, запись устаревшего ответа в кэш — тесты R1, R8, R12.
- ❌ Кэш внутри стора vedro — ревью.
- ❌ Подписка или таймер без отписки — ревью, тест повторного монтирования.
