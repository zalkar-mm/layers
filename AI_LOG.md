## 2026-09-26 · Этап 0, задача 0.8: проверка находок vedro

**Инструменты:** Claude (Cowork) — основной агент, без субагентов: задача небольшая, одна зона файлов.

**Исследование.** AI прочитал скомпилированный `node_modules/vedro/lib` целиком (~480 строк), сопоставил каждую находку V1–V7 с конкретной строкой и написал по тесту на находку. По ходу найдено новое поведение N1: `get()` без ключа возвращает копию состояния, поэтому не годится как `getSnapshot` для `useSyncExternalStore`. Это влияет на проектирование хуков §4.3.

**Итог:** V1–V7 подтверждены. Для V2, V6 и V7 найдены уточнения, в том числе к формулировке ТЗ §0 (V2: строковая форма `dispatch` добавляет новый ключ без проверки).

**Где AI ошибся и как поймано:**

- В тесте V3 AI ожидал ровно 2 × N вызовов `JSON.stringify`, получилось 2 × N + 2. Лишние два вызова — проверка ключей внутри самого `dispatch` (`areKeysEqual`), AI её не учёл. Поймано запуском теста, причина найдена в исходниках, ожидание уточнено с комментарием.
- Тест V2 с объектом `{ extra: true }` не компилировался: TypeScript отклоняет объект без общих полей со стором (weak type). Поймано `yarn typecheck`, объект заменён на `{ count: 1, extra: true }`.
- В тесте V4 переменная, присваиваемая внутри компонента, сузилась до `never`. Поймано `yarn typecheck`, заменено на объект-держатель.

**Ограничение:** проверка в jsdom, а не в браузере, как просит ТЗ 0.8. Вынесено на решение заказчика.

**Проверено руками (запуском):** `yarn check` — 16 тестов, lint, steiger, typecheck, build.

## 2026-09-26 · Этап 2: mock API

**Инструменты:** Claude (Cowork) — основной агент, без субагентов (один модуль).

**Проектирование.** Типы данных (GeoJSON-сетка) перенесены из `entities/layer` в `shared/api/mock-layer-api`: по FSD `shared` не может импортировать `entities`, а mock должен возвращать `LayerData`. Сущность реэкспортирует тип. Mock не знает о реестре: параметры слоя (диапазон, нужно ли направление) даёт вызывающий через `describeLayer` — так контракт `fetchLayerData(id, { signal })` сохранён. Детерминизм: на каждый запрос из генератора берутся ровно четыре числа в одном порядке, поэтому при одном seed последовательность запросов воспроизводится полностью.

**Тесты раньше кода:** 14 тестов по §4.4 написаны до реализации — сетка и bbox, диапазон значений, направление ветра, плавность поля, задержка в [min, max], доля ошибок, детерминизм, abort с очисткой таймера.

**Где AI ошибся и как поймано:** `isAbortError` проверял `error instanceof Error`. В jsdom `DOMException` не наследует `Error` — два теста отмены упали. Проверка переписана на имя ошибки (так же проверяют отмену реального `fetch`).

**Проверено руками (запуском):** `yarn check` — 44 теста.

**Инструменты:** Claude (Cowork) — основной агент пишет код и тесты; отдельный субагент-ревьюер со свежим контекстом проверяет этапы 2–4 и подтверждает гипотезы экспериментами в копии проекта.

**Проектирование.** Машина состояний — чистые функции (`transitions.ts`): при несовпадении `requestId` возвращают тот же объект. Кэш SWR вне стора с LRU и TTL (ADR 006). Движок команд вынесен в `entities/layer` (ADR 008): одиночные и массовые команды обязаны делить один набор abort-контроллеров, а FSD запрещает импорт между фичами. Лог событий — отдельный маленький стор vedro.

**Тесты R1–R15** написаны по таблице §6. После того как все 57 тестов прошли с первого запуска, AI проверил их мутациями: убрал проверку `requestId` (упали R1, R8), убрал abort (упали R5, R6 и тест disable), перенёс запись в кэш до проверки (упал R12). Первая попытка третьей мутации не применилась — Prettier разбил сигнатуру на строки, и замена по строке не нашла совпадения; поймано проверкой, что мутация вообще попала в файл.

**Ревью (субагент) нашло, AI перепроверил и исправил:**

- P1: retry и refresh показывали stale старше TTL — нарушение §5.3. Добавлена проверка свежести и тест.
- P1: тест «V4» в хуках не ловил проблему: ревьюер подставил наивный хук на `useState` + `useEffect`, тесты остались зелёными. Тест переписан на `dispatch` из layout-эффекта соседа; наивный хук теперь роняет его.
- P1: LRU при чтении и события лога не были покрыты тестами. Добавлены `cache.test.ts` и проверки событий в R1, R10, R12, R13 и `disable`.
- P1: если подписчик стора синхронно вызывал команду во время `dispatch`, запрос оставался в полёте без контроллера. Контроллеры регистрируются до `dispatch`; устаревший ответ чистит свою запись. Добавлен тест.
- P2: синхронный `throw` транспорта оставлял слои в `loading` навсегда; при выключенном кэше лог писал «кэш обновлён», а счётчик показывал записи; событие `cache-expired` не отправлялось; просроченные записи занимали места LRU. Всё исправлено и покрыто тестами.
- В `docs/vedro-findings` пути к исходникам были указаны как `lib/internal/…` вместо `lib/_internal/…` — исправлено.

## 2026-09-26 · Этапы 5–6: панель слоёв и бюджет рендеров

**Инструменты:** Claude (Cowork) — основной агент, без субагентов.

**Проектирование.** `LayerRow` в `memo`, получает только `id`, остальное берёт через `useLayer(id)`. Обработчики — стрелки на DOM-элементах (у `memo` их нет) или модульные функции; `dispatch` в пропсах нет. Тик «N мин назад» живёт в бейдже статуса, а не в строке: при тике перерисовывается только бейдж. Счётчик рендеров считает коммиты и пишет число прямо в DOM из layout-эффекта — сам не вызывает рендеров. Переключатель «Показать рендеры» — атрибут на `<html>`, без состояния React. В прод-сборку счётчик попадает только с `VITE_RENDER_COUNTS=true` (сборка демо).

**Где AI ошибся и как поймано:**

- Экземпляры приложения получили `now: Date.now` — ссылку на настоящую функцию, сохранённую при загрузке модуля. Фейковые таймеры её не подменяют: в тесте «Готово · 18 мс» вместо «500 мс». Поймано тестом бюджета, заменено на `() => Date.now()`.
- В тесте `enableAll` AI ждал два рендера шапки, их было четыре. Разбор показал, что поведение верное: три ответа — три `dispatch`, число загружающихся меняется 3 → 2 → 1 → 0, и шапка обязана это показать (§8: «если меняется число loading»). Исправлено ожидание, а не код; причина записана в комментарии теста.
- `userEvent` с фейковыми таймерами Vitest зависал: RTL прокручивает `setTimeout(0)` только для таймеров Jest. В тестах бюджета — `fireEvent`, исключение записано в `testing.md`.
- Первая пачка файлов фич записалась не в проект: команда `cd` в несуществующую папку упала, и `mkdir` создал файлы в домашнем каталоге. Замечено по выводу команды, файлы перенесены.

**Проверка тестов мутацией:** строка подписана на весь `byId` → падают 6 из 7 тестов бюджета (седьмой — тик, от подписки не зависит).

**Проверено руками (запуском):** `yarn check` — 122 теста.

## 2026-09-26 · Этапы 7–8: Chaos-панель, стресс-режим, замеры

**Инструменты:** Claude (Cowork) — основной агент. Замеры в браузере — Playwright в облачной среде (в VM Cowork нельзя скачать Chromium); сравнение подписок — Vitest в VM.

**Сделано.** Chaos-панель: задержка, доля ошибок, seed, спам-клик (20 переключений за 500 мс), кэш (вкл/выкл, TTL, очистка, «в кэше: N из 50»), лог 20 событий. Стресс-режим 3 · 100 · 1000 через тот же реестр, виртуализация списка с 50 строк. ADR 003 с цифрами.

**Где AI ошибся и как поймано:**

- **Прод-сборка падала сразу при запуске**, а 134 зелёных теста этого не видели. vedro — CommonJS-пакет: Vitest отдаёт класс по `import Vedro from 'vedro'`, а Rolldown в прод-сборке — объект `exports`. Поймано первым запуском в браузере (пустая страница, `default is not a constructor`). Исправлено адаптером `createVedroStore` в `shared/lib/vedro`; прямой импорт vedro в `src` запрещён ESLint. Регрессию ловит e2e smoke-тест: он собирает прод-версию.
- **Первый замер «штатный useSelector против нашего хука» показал равенство.** Вывод «ADR 002 не нужен» был бы ошибкой: в замере слои были пустыми. С загруженными GeoJSON-данными (765 ячеек) разница — 0,73 мс против 1148 мс на действие при 1000 слоях. В `perf/RESULTS.md` оставлены оба сценария.
- **Замер в браузере показал +6 рендеров у чужой строки** при переключении слоя в режиме 1000. Разбор: строка вошла в зону виртуализации, когда соседняя изменила высоту, — это монтирование, а не перерисовка. Методика исправлена: монтирования считаются отдельно.
- **`enableAll` на 1000 слоях занимал 21,9 мс.** Причина — 1000 отдельных `dispatch` в лог событий. События команды теперь уходят одной пачкой: 13,2 мс. `disableAll` остался 24,8 мс (1000 отмен в mock) — записано честно, порог 16 мс здесь не выполнен.
- Тест виртуализации в jsdom сначала не видел строк: виртуализатор меряет контейнер через `offsetHeight`, которого в jsdom нет. AI дважды подставил не то (`getBoundingClientRect`), прежде чем прочитал исходник `@tanstack/virtual-core`.
- В Vitest 5 нет API `bench`. Замер сделан обычным тестом с `performance.now()`, который запускается только по флагу `VITE_PERF=1`.

**Проверено руками (запуском):** `yarn check` — 136 тестов; e2e smoke — desktop и mobile; замеры — `perf/RESULTS.md`.

## 2026-09-26 · Этап 9: карта

**Инструменты:** Claude (Cowork) — основной агент. Проверка в браузере — Playwright в облачной среде со снимками экрана, которые AI смотрит сам.

**Сделано.** `MapView` рендерится один раз, `MapSync` вне React работает через узкий `MapPort` (ADR 005). Заливки по палитре реестра, стрелки ветра с поворотом по `direction` и размером по скорости, ветер поверх заливок, stale-данные на карте, `setData` без мигания, лимит 10 слоёв в стресс-режиме, легенда, «Загружается: …», значения по клику. Добавлена зависимость `@types/geojson`: без неё TypeScript не проверяет данные, которые мы отдаём MapLibre.

**Где AI ошибся и как поймано** (всё — первым запуском в браузере; тесты в jsdom этих ошибок не видят):

- **Карта не рисовала слои: не грузился воркер MapLibre.** MapLibre 6 ищет воркер рядом со своим модулем, а после сборки Vite файла там нет. Исправлено через `?worker&url` и `setWorkerUrl`.
- **Контейнер карты схлопывался в высоту 0.** CSS MapLibre вешает `position: relative` и перебивает `inset: 0`. Поймано по размеру холста 1080×300, найдено по снимку экрана. Размер задан явно.
- **Без подложки слои не появлялись вовсе.** `MapSync` ждал события `load`, которого нет, если стиль подложки не загрузился. Добавлены запасной пустой стиль и старт по `load` или `style.load`. В облачной среде OpenFreeMap заблокирован — так этот сценарий и нашёлся.
- **Подсказка по клику не показывала ветер.** `queryRenderedFeatures` находит стрелку, только если клик попал точно в неё. Значения теперь считаются по данным слоёв, порядок — как в списке.
- В тесте карты слой сразу показывался «из кэша»: предыдущий тест оставил данные в общем кэше. Добавлена очистка кэша перед каждым тестом.

**Проверено руками (запуском):** `yarn check` — 160 тестов; снимок карты с тремя слоями и подсказкой — Chromium, прод-сборка. Подложка OpenFreeMap в облачной среде недоступна (403 от прокси); у пользователя в браузере не проверялась.

## 2026-09-26 · Этапы 10–12: URL, доступность, E2E, финальное ревью

**Инструменты:** Claude (Cowork) — основной агент; субагент-ревьюер со свежим контекстом проверил этапы 5–12 и подтверждал гипотезы экспериментами в копии проекта. E2E — Playwright в облачной среде, desktop 1440×900 и mobile 360×740.

**Сделано.** URL: чтение в загрузчике маршрута React Router (до первого рендера), запись вне React — подписка на стор, debounce 300 мс, `history.replaceState`. Доступность: нативные радиокнопки для 3 · 100 · 1000, связка вкладок и панелей, `role="status"` у статусов. E2E: сценарии E1–E5 и клавиатура в браузере. GIF для README — кадры Playwright, собранные в Pillow.

**Решение, которое AI принял сам:** запись в URL идёт через `history.replaceState`, а не через `router.navigate`. Навигация роутера перерисовала бы дерево маршрута, и движение слайдера рендерило бы страницу и карту — нарушение §8. Чтение — через загрузчик роутера.

**Где AI ошибся и как поймано:**

- Проверку стрелок у слайдера AI написал в jsdom — там их нет, это поведение браузера. Поймано падением теста; проверка перенесена в e2e.
- E3 сначала ждал окончания спам-клика фиксированной паузой. Заменено: кнопка неактивна, пока идёт серия, тест ждёт её возврата.
- Perf-замер перестал находить переключатель 3 · 100 · 1000 после перехода на нативные радиокнопки: скрытый input перекрыт подписью. Клик — по подписи.

**Ревью (субагент) нашло, AI перепроверил и исправил:**

- P1: в стресс-режиме синтетические слои писались в URL, а ссылка на реальные слои затиралась. Ссылка из стресс-режима не воспроизводится — страница открывается в режиме 3. Ревьюер подтвердил тестом. В стресс-режиме URL теперь не пишется; добавлен тест.
- P1: строка §8 «любое действие в режиме 1000» была проверена только на слайдере. Добавлены тесты включения, ответа, ошибки со сменой высоты строки и `enableAll` — последний сверяет число перерисованных строк с числом строк в DOM.
- P1: в StrictMode первая карта успевала создаться до отмены, а её `remove()` мог снять классы MapLibre с общего контейнера. `loadMap` получает `AbortSignal` и не создаёт карту после отмены; добавлен тест с подменой модуля MapLibre.
- P2: невалидная разметка виртуального списка (`ul > div > li`); двойное объявление ошибки (`status` + `alert`); поле seed нельзя было очистить; запасная подложка включалась на любую первую ошибку, а не только на ошибку стиля; E4 не проверял, что история не растёт. Всё исправлено.

## 2026-09-26 · Этап 13: замеры в браузере и оптимизация массовых команд

**Инструменты:** Claude (Cowork); Playwright и Chromium 141 в облачной среде; CPU-профили и трассировка через Chrome DevTools Protocol; Event Timing API для задержки до кадра.

**Сделано.** Пересобран замер: теперь он включает коммит React. Найдены и убраны две причины, по которым `enableAll` и `disableAll` на 1000 слоях не укладывались в 16 мс. Итог: 5–9 мс от dispatch до commit ([perf/RESULTS.md](perf/RESULTS.md)).

**Где AI ошибся и как поймано:**

- **Замер не включал коммит.** В комментарии к perf-тесту было написано, что React коммитит до выхода из обработчика клика. Трассировка показала блок `RunMicrotasks` после обработчика: React 19 коммитит обновления из `useSyncExternalStore` в микрозадаче. Замер дополнен временем до конца микрозадач, поставленных кликом; старые числа в документах заменены.
- Первая попытка «полного» замера ждала следующую задачу через `MessageChannel`. Туда попадал и отложенный старт запросов, и числа выходили завышенными. Заменено на микрозадачу, поставленную после клика.

**Решения, которые AI принял сам:**

- `disableAll`: CPU-профиль показал, что больше половины времени уходит в `cancel`. `abort()` без аргумента создаёт `DOMException` со стеком, а mock создавал ещё один на отклонение промиса. У сервиса теперь одна причина отмены на все запросы; mock отклоняет промис с `signal.reason`, как настоящий `fetch`. Было 18,7–22,9 мс синхронно, стало 3,5–4,9 мс.
- `enableAll`: 1000 `AbortController`, таймеров и промисов mock стояли между dispatch и commit. От 50 запросов их старт откладывается в следующую задачу (`defer` в зависимостях сервиса). Сначала коммит и отрисовка loading, потом запросы. Одиночные команды остались синхронными, тесты команд без `defer` не изменились. Защита от гонок не ослабла: контроллеры регистрируются до dispatch, и отложенный старт пропускает уже отменённые. Это покрыто новыми тестами: выключение до старта и повторный `enableAll` до старта.

**Проверено руками (запуском):** три прогона `PERF=1 yarn e2e perf.spec.ts`, профили до и после; `yarn check`; `yarn e2e` — 14 сценариев на desktop и mobile.

## 2026-09-26 · Этап 14: исправление багов из QA-прогона

**Инструменты:** Claude (Cowork); отчёт QA — внешний прогон с тремя багами.

**Исправлено:**

- **БАГ-1, возврат из стресс-режима терял слои и ссылку.** `switchLayerSet` пересоздавал стор, а синхронизация URL через 300 мс писала пустое состояние. Теперь при уходе из набора слоёв сохраняется снимок: включённость и прозрачность. `setStressMode` возвращает набор в оставленном виде: прозрачность одним `dispatch`, включение — обычной командой (новая `enableLayers`), со stale из кэша и защитой от гонок. URL после возврата пишется из восстановленного состояния. Предложение QA — заново применять `applyUrlState` — не взято: URL пишется с задержкой, и изменение за последние 300 мс перед переходом потерялось бы. Кроме того, стресс-режим тогда зависел бы от фичи URL, а FSD запрещает импорт между фичами. Без флага `restore` стор по-прежнему сбрасывается: на этом держатся сбросы в тестах.
- **БАГ-2, у переключателя «3 · 100 · 1000» не было имени группы в дереве доступности.** `fieldset` со скрытой `legend` давал `group`, но не `radiogroup`, и QA не нашёл группу. Добавлены `role="radiogroup"` и `aria-labelledby` на `legend`.
- **БАГ-3, повторы в CI скрывали нестабильные тесты.** `retries: 0` везде.

**Тесты:** два юнит-теста стресс-режима (возврат в 3 и возврат в стресс-набор), тест синхронизации URL на сохранность ссылки, e2e E6 (сценарий QA в браузере) и проверка `radiogroup` в a11y. E6 проверен мутацией: без восстановления падает на `aria-checked`.

**Проверено руками (запуском):** `yarn check` — 194 теста; `yarn e2e` — 18 сценариев на desktop и mobile.

## 2026-09-26 · Этап 15: БАГ-4 — вторая защита от гонок не была видна в приложении

**Проблема (QA).** Mock API всегда честно отменял запрос, поэтому проверка `requestId` в работающем приложении не срабатывала: в логе были только `запрос` и `abort`. README при этом обещал ревьюеру `отброшен (устаревший)` после спам-клика. Проверку номера запроса подтверждали только тесты R8 и R12.

**Исправлено.** В mock API добавлена настройка `ignoreAbort`, в Chaos-панели — переключатель «Сервер отвечает, несмотря на отмену». Так ведёт себя запрос, который уже ушёл в сеть: ответ приходит после `abort`. Сервис отбрасывает его по номеру запроса, в логе видно `отброшен (устаревший)`, стор и кэш не меняются. По умолчанию переключатель выключен: mock ведёт себя как `fetch`. README, пункт 3, переписан: что видно без переключателя, что — с ним, и что `из кэша` появляется, только если слой уже был загружен.

**Тесты:** два теста mock (ответ после отмены; ответ на уже отменённый signal), два теста Chaos-панели (с переключателем в логе есть `stale-dropped`, без него — нет), e2e E3b в браузере. E3 и E3b прогнаны по 5 раз на desktop и mobile без падений.

**Проверено руками (запуском):** `yarn check` — 198 тестов; `yarn e2e` — 20 сценариев.

## 2026-09-27 · Этап 16: ревью алгоритмической сложности и код без комментариев

**Запрос.** Найти места с квадратичной сложностью и оптимизировать. Начать с цикла в цикле в `grid.ts`. Убрать комментарии из кода.

**Разбор `grid.ts`.** Цикл в цикле там по строкам и столбцам сетки — это O(ячеек): каждая ячейка создаётся один раз, это размер результата. Квадратичной сложности нет. Лишняя работа была другая: синусы и косинусы считались на каждую ячейку, хотя зависят только от столбца или только от строки. Теперь они считаются один раз на столбец и строку. Тригонометрии в 12 раз меньше, сетка на 35 % быстрее, результат побитово тот же.

**Настоящее O(n²) нашлось в загрузке.** CPU-профиль после «Включить все» показал: каждый из n ответов делал `dispatch`, а каждый `dispatch` — несколько проходов по всем n слоям (копия `byId`, сводка, включённые, `MapSync`, URL). Со 100 до 1000 слоёв время стора выросло в 13 раз. Ответы массовой загрузки теперь применяются пачкой за 16 мс. Стор, React и карта на 1000 слоях: 480–820 мс → 48–90 мс за всю загрузку ([perf/RESULTS.md](perf/RESULTS.md)).

**Остальное по ревью:**

- `MapSync` искал первые 10 включённых слоёв фильтром по всему списку. Теперь поиск останавливается на десятом.
- Поиск ячейки под курсором создавал два массива и разворачивал их в `Math.min(...)` на каждую из 765 ячеек. Теперь это проход без выделения памяти.
- Больше вложенных проходов нет. Проверены стор, селекторы, кэш (LRU до 50 записей), парсинг URL, реестр (Map), лог (20 событий).

**Комментарии.** Удалены все: 343 из TS/TSX-файлов — AST-скриптом на компиляторе TypeScript, чтобы не задеть `//` в строках и URL — плюс CSS-комментарии в styled-компонентах и YAML-комментарии в workflow. Оставлены только директивы: `eslint-disable-next-line`, `@ts-expect-error` в тестах типов, `/// <reference>`. Названия переименованы там, где смысл держался на комментарии:

| Было | Стало |
|---|---|
| `batched` | `withBatchedEvents` |
| `buffer` | `eventBuffer` |
| `failures` | `failedAttempts` |
| `defer` | `scheduleBulkRequests` |
| `DEFER_REQUESTS_FROM` | `BULK_LAYERS_THRESHOLD` |

Правило code-style §2 переписано: комментариев в коде нет, обоснования — в ADR, `AI_LOG.md` и названиях тестов. Для `@ts-expect-error` в тестах описание больше не требуется (`ban-ts-comment`).

**Тесты:** три новых теста пачки ответов:

- 100 ответов дают один `dispatch`;
- слой, выключенный до применения, ответ не получает;
- при меньше 50 запросов в полёте ответ применяется сразу.

**Проверено руками (запуском):** `yarn check` — 201 тест; `yarn e2e` — 20 сценариев; CPU-профили до и после.

## 2026-09-27 · Этап 17: общая геометрия сетки mock API

**Поправка к этапу 16.** Сложность `generateGrid` AI назвал линейной. Точнее так: O(rows × cols), то есть квадратичная по стороне сетки и линейная по числу ячеек. Пользователь указал на неточность.

**Сделано.** Координаты полигонов одинаковы у всех слоёв и запросов. Геометрия теперь строится один раз при загрузке модуля, одним проходом по индексу ячейки, без вложенного цикла, и замораживается. Каждый ответ ссылается на неё и считает только `value` и `direction`. Сетка стала быстрее в 2,8 раза по сравнению с исходной версией: 0,43–0,49 → 0,15–0,17 мс. Результат побитово тот же.

**Риск и защита.** Общая геометрия — общее изменяемое состояние. Если кто-то изменит полигон в одном ответе, сломаются все. Поэтому она заморожена: попытка изменения бросает `TypeError`, это проверено тестом. MapLibre данные не меняет: `setData` копирует их в воркер.

**Тесты:** два ответа ссылаются на одну геометрию, но значения у них разные; геометрия заморожена, изменение бросает `TypeError`.
