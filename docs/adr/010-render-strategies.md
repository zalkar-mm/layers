# ADR 010: Вид отрисовки слоя — карты `Record<LayerRenderKind, …>`, а не проверки `render === 'arrows'`

**Статус:** Принято
**Дата:** 2026-09-28
**Этап ТЗ:** 9 (пересмотр), ревью по внешнему своду правил — [AI_LOG, этап 22](../../AI_LOG.md#2026-09-28--этап-22-баг-с-видом-отрисовки-heatmap)

## Контекст

В ТЗ §4.1 и в типе `LayerRenderKind` три вида отрисовки: `fill`, `arrows`, `heatmap`. Код в пяти местах проверял только `render === 'arrows'`, всё остальное рисовал заливкой. Слой с `heatmap` молча нарисовался бы заливкой, компилятор бы не подсказал. Ни один из трёх базовых слоёв сейчас не `heatmap`, поэтому ошибка была скрытой.

От вида зависят: нужно ли направление в данных mock API, тип слоя MapLibre, свойство прозрачности, стиль, порядок на карте и форма данных источника.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Оставить `if (render === 'arrows')`, добавить ветку `heatmap` | Минимальный diff | Пять мест, следующий вид снова молча уйдёт в `else` |
| Исчерпывающий `switch` в каждом месте | Компилятор ловит новый вид | Пять `switch` с одинаковыми ветками; сужение union здесь не нужно — это справочник ([code-style §5](../rules/code-style.md#5-jsx)) |
| **Карта стратегий `Record<LayerRenderKind, …>`** | Вид описан в одном месте; неполная карта не компилируется; новый вид — одна запись (OCP) | Ещё один модуль в `map-view/model/sync` |

## Решение

Две карты по слоям FSD:

- `RENDER_KIND_TRAITS` в [`entities/layer/config/render-kind-traits.ts`](../../src/entities/layer/config/render-kind-traits.ts) — свойства вида, нужные сущности: `withDirection` для запроса к mock API.
- `RENDER_STRATEGIES` в [`widgets/map-view/model/sync/render-strategies.ts`](../../src/widgets/map-view/model/sync/render-strategies.ts) — всё про MapLibre: `mapLayerKind`, `opacityProperty`, `stackRank`, `style`, `toSourceData`. `MapSync` берёт стратегию по `config.render` и не знает про конкретные виды.

`heatmap` — настоящая тепловая карта MapLibre по центроидам ячеек ([`cell-centroids.ts`](../../src/widgets/map-view/lib/cell-centroids.ts)): heatmap-слой принимает точки, а mock отдаёт полигоны. Подсказка по клику ищет ячейку по исходным полигонам.

Порядок на карте — по `stackRank`: заливки (0) → heatmap (1) → стрелки (2), в любом порядке включения. Стрелки всегда видны поверх полей.

Параметры heatmap подобраны в браузере на временном конфиге (инсоляция как `heatmap`):

- вес — значение, нормированное по `valueRange` в [0, 1];
- радиус 12 → 192 px по zoom 4 → 8, экспоненциально (основание 2) — ячейки сливаются в ровное поле, без «гороха»;
- интенсивность 0,5;
- палитра слоя начинается с плотности 0,02, ниже — прозрачный. Первая версия смешивала палитру с прозрачным чёрным, и цвета выходили серыми.

## Последствия

- Новый вид отрисовки = запись в обеих картах; без неё проект не компилируется.
- `MapSync` и `layer-api` не ветвятся по виду.
- Heatmap пересчитывает центроиды при каждом новом ответе: O(ячеек), 765 точек на слой.
- В реестре слоёв heatmap сейчас не используется: путь проверен тестами и вручную в браузере, в демо его не видно.
- Проверяется: тесты типов «без описания одного из видов не компилируется» (`render-strategies.test.ts`, `render-kind-traits.test.ts`), `cell-centroids.test.ts`, `map-sync.test.ts` › heatmap и порядок слоёв, `layer-api.test.ts`.
