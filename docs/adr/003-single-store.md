# ADR 003: Один стор, а не стор на слой

**Статус:** Принято
**Дата:** 2026-09-26
**Этап ТЗ:** 8

## Контекст

При 1000 слоях каждый `dispatch` оповещает всех подписчиков `@state` — 1000 строк. Альтернатива — шардинг: отдельный стор vedro на слой, строка подписана только на свой.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Один стор `ids + byId`** | Одна точка правды; массовые команды — один `dispatch`; сводка считается по одному снимку | Каждое изменение будит всех подписчиков |
| Стор на слой | Изменение будит одного подписчика | 1000 сторов; `enableAll` — 1000 `dispatch`; сводка и MapSync собирают состояние из 1000 источников; смена набора слоёв пересоздаёт сторы |

## Решение

Один стор. Цена «разбудить всех» мала, потому что подписчик делает O(1) чтение по ссылке и перерисовывается, только если его снимок изменился (ADR 002). Замер в браузере на 1000 слоях ([perf/RESULTS.md](../../perf/RESULTS.md)): вкл/выкл одного слоя — 1,7–3,1 мс, движение слайдера — 1,2–1,3 мс от dispatch до commit, перерисована одна строка. Порог ТЗ — 16 мс. Шардинг решал бы проблему, которой нет, и усложнял массовые команды.

## Последствия

- Если действие с одним слоем на 1000 слоях станет дороже 16 мс — первым делом смотреть не на стор, а на снимки: не отдаёт ли кто-то новый объект на каждый вызов.
- Массовые команды остаются одним `dispatch` (ТЗ §5).
