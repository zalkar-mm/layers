# ADR 005: Синхронизация карты вне React

**Статус:** Принято
**Дата:** 2026-09-26
**Этап ТЗ:** 9

## Контекст

Карта — внешняя императивная система (MapLibre). Движение слайдера меняет прозрачность слоя десятки раз в секунду. ТЗ §8: карта не должна перерисовываться React при движении слайдера.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Декларативная обёртка (`react-map-gl` и аналоги), слои как JSX | Привычно | Каждое изменение слоя — рендер компонента карты и сравнение пропсов; новая зависимость |
| Компонент карты подписан на стор хуком | Без зависимостей | Тот же рендер карты на каждое движение слайдера |
| **MapSync вне React** | 0 рендеров карты; изменения точечные | Своя логика сравнения слоёв |

## Решение

`MapView` рендерится один раз: создаёт карту и `MapSync`, освобождает их при размонтировании. `MapSync` подписан на `byId` через `store.on` (V7), сравнивает каждый слой по ссылке и вызывает только нужные методы MapLibre: прозрачность — `setPaintProperty`, новые данные — `setData` без удаления слоя, выключение — удаление слоя и источника. MapSync работает с узким интерфейсом `MapPort`, адаптер MapLibre — отдельный файл; в тестах — фейк, записывающий вызовы.

Легенда и индикатор «Загружается: …» — React-компоненты, но подписаны на статус слоя примитивом (`useLayerMapStatus`): прозрачность их не перерисовывает.

## Последствия

- Движение слайдера: 0 рендеров `MapView` и легенды (тест `map-view.test.tsx`), один `setPaintProperty` (тест `map-sync.test.ts`).
- MapLibre (~1 МБ) грузится динамически отдельным чанком; воркер собирается через `?worker&url` — MapLibre 6 ищет его рядом со своим модулем, а после сборки его там нет.
- Без WebGL или без подложки приложение работает: заглушка вместо карты или слои на пустом фоне.
- Значения по клику считаются по данным слоёв, а не по отрисованным фигурам: иначе скорость ветра видна, только если попасть курсором в стрелку.
